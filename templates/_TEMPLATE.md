# <name>: <role, at most 72 characters, no em-dash: what it is + its role (the INDEX row shows it; more detail goes in ## role)>

## tldr

3-6 dense sentences, at most 800 characters: what it does, where it runs, what feeds it, what it feeds, current state. No dates, PR numbers or history.

## role

- Why it exists; which system flow(s) it participates in (name the flow as ARCHITECTURE.md names it).
- Upstream callers and inputs; downstream callees and outputs. Name repos, queues, buckets, endpoints.

## architecture

- Module, crate or package map: path, then responsibility (one bullet each; cover ALL top-level modules).
- Key abstractions and entry points with paths (main.rs, Application.java, hooks.server.ts, ...).
- Concurrency and process model if a service (threads, async tasks, cron, queue consumers).

## data

- Databases, tables (names + purpose), migration dir and tool, buckets, queues (exact names), caches, on-disk formats.
- Ownership: which data this repo is the source of truth for.

## interfaces

- HTTP: table route, method, handler path, auth, purpose. ALL routes for services.
- CLI: commands and flags table if a CLI.
- Events and queues consumed and produced (exchange and queue names, payload shape pointers).
- File formats read and written (with spec or struct paths).
- Public API surface if a library (key classes and functions).

## configuration

- Env vars, config files, secrets: name, purpose, where read (path). Include chart values that matter.

## build-test-run

- Exact commands that work (build, lint, test, run locally), incl. toolchain pins (JDK, node, rust) and known local caveats.

## cicd

- Workflows in .github/workflows: file, trigger, what it does.
- Release path: how a change reaches each environment; versioning scheme; image and chart publication.

## keyfiles

Table: "to change X", then file(s). Cover the 8-15 most likely change tasks for this repo.

## invariants

- Gotchas, constraints, sharp edges, things that look wrong but are intentional, data-safety rules.

## recent

- <YYYY-MM-DD>: PR #N (merge <sha7>) <what changed>. The newest 5 merged PRs on the default branch, merge date in the workspace's timezone; `flax atlas recent --write --doc <name>` checks and adds them.
